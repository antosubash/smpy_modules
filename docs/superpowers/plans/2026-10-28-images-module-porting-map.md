**Static findings beyond design Context (phase 2):**
- **Direct base64 duplicate race is not idempotent:** precheck `B/routes_upload.py:443`; a concurrent unique violation from `:130` is rolled back/cleaned but re-raised at `:131`, while caller catches only MinIO errors at `:479`. Same duplicate returns success sequentially, 500 concurrently. Module should recheck identity after IntegrityError, as download path does.
- **Partial rendition success is marked complete:** per-size generate/upload failures swallowed (`B/pipeline/thumbnails.py:123`, `:221`, `:248`); any nonempty subset → COMPLETED at `:330`. Normal retry then skips missing sizes. Make required size completion explicit/retryable; don't retain partial-as-final semantics.
- **Rendition replacement loses old rows on failed regeneration:** deletes + commits before checking error/status (`B/pipeline/thumbnails.py:282`, `:289`, `:304`). Keep old rendition rows until replacement can commit; don't leave fallbacks unexpectedly serving full images.
- **Metadata capture time overwritten:** `_update_image_from_result` protects location but blindly replaces existing manual/import `captured_at` when EXIF has one (`B/pipeline/geolocation.py:301`). Decide precedence consistently; design explicitly requires location precedence, so capture-time precedence is a porting decision, not an approved requirement.
